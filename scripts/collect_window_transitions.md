# ColorOS 17 状态栏随应用过渡：采集说明

用于分析状态栏能否跟随打开应用、返回桌面和最近任务切换动画。需要手机已 Root。

1. 把 `collect_window_transitions.sh` 放到手机的 **Download / 下载** 目录。
2. 在手机终端执行：

   ```sh
   su -c 'sh /sdcard/Download/collect_window_transitions.sh --sample'
   ```

3. 等终端提示“现在开始采样”后，手动打开一个普通应用、返回桌面，再从最近任务切换应用。共采样 6 次，服务响应正常时约 20 秒。采样只是辅助状态记录，不要求精确操作；错过也可以先发回采集包。
4. 等待“采集包”提示，将下载目录中的 `thunder-window-transitions-日期-时间-编号.tar.gz` 发回。

不需要先重启、关闭模块或调整系统动画速度。只导出代码及静态状态时，去掉 `--sample` 即可。复制与压缩耗时、采集包大小随固件而异，框架和编译文件可能较大。

脚本收集实际桌面及常见 ColorOS 桌面包、SystemUI 和插件的 APK（包含分包），各系统分区的框架 JAR、系统类路径中的 JAR，以及可找到的 `.odex` / `.vdex` / `.oat` 等编译文件。文件保留来源路径，并附带复制清单、DEX 检查结果和运行状态。包管理器查询失败时还会直接查找相关 APK；单次服务查询最多等待 20 秒。

脚本只向输出目录和同名压缩包写入文件，不修改设置、不重启进程、不自动打开应用，也不启用系统追踪。窗口和图层状态可能含应用名称、窗口标题及路径；不采集应用私有数据、通知内容、截图、录屏或完整日志。

即使显示 `NO`、查询超时或命令不支持，也请先发回生成的包，里面的记录可用于判断缺什么。`dex=no` 表示 APK/JAR 里未发现内嵌 DEX，需结合编译文件分析，并不代表没有复制成功。压缩失败或中断时原目录会保留；可用文件管理器手动压缩。
