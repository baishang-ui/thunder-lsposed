# thunder

适用于 ColorOS 17 的独立 LSPosed 模块，同时提供系统设置集成入口，调整 SystemUI 的下拉背景、通知横幅、通知边距、流体云外观与状态栏图标显示。设置自动保存，改动的组件旁可回退。

当前版本 **8.0 / versionCode 13**，应用包名及源码命名空间统一为 `io.github.baishangui.thunder`，配置格式为 `thunder.settings`。

## 环境要求

- Android 17 / SDK 37，目标适配 ColorOS 17.0.0.104（CN01）的 SystemUI。
- 支持 **libxposed API 102** 的 LSPosed。管理器版本号不能替代实际连接检查，以应用主页的连接状态和运行报告为准。
- 外观效果通过 SystemUI 进程中的 Hook 实现；应用内同步配置无需 Root 授权。

系统设置的 COUI 控件创建与参数绑定已在连接的 ColorOS 17 真机上检查；实际 LSPosed 设置入口、各 Hook 的视觉效果和性能仍需启用对应作用域后验收。其他 ColorOS 版本的内部接口可能不同。流体云的原生背景模糊依赖设备固件提供的 ViewRootManager 后端。

## 音量面板

“调节 → 音量 → 音量面板”支持音量条长宽、圆角、背景混色与模糊，按钮为正方形，边长、圆角、混色与模糊统一跟随音量条。开启“跟随音量条展开”后，继续使用系统的音量行、弹簧动画与收起流程，音量条尺寸跟随主音量条，下方提供可直接点选的响铃／振动／静音三段式与免打扰，四格铺满底部，使用系统图标并带选中块滑动和图标过渡，隐藏标题、提示、设置入口及文字标签。面板按音量条与快捷按钮的组合尺寸包裹内容，间距与四周留白统一为 8 dp；从当前音量条位置横向展开，保持纵向位置并保留原生宽度过渡。安装更新后需正常重启手机；参数随后实时同步。已加入原生流程保留与几何回归，动画观感和触摸手感仍需目标真机验证。实现与验收见 [音量面板说明](docs/volume-panel.md)。

## 配置实时应用与系统界面重启

- 修改参数自动保存，并通过 API 102 远程配置监听实时应用。SystemUI 和独立插件进程在工作线程读取完整快照，合并同次提交的通知，并刷新现有背景代理与状态栏图标。已有视图缓存的布局参数可能需要重新展开对应界面。
- 右上角“重启系统界面”点击即执行：保存并尝试同步配置后请求 Root，只对精确核验的 `com.android.systemui` PID 执行一次 `kill -9`，由系统重建，必要时补启动 SystemUI 服务。不再弹出二次确认、等待 Hook 报告或强制等待 65 秒，也不停止独立的系统界面插件。自动调参仍只走实时配置。
- 已核对官方 LSPosed 2.2.1 (7912)：SystemUI Binder 存活不足 60 秒时退出仍会累计保护次数。本操作按用户点击立即执行，不修改框架安全模式开关或计数。已进入安全模式时，需要按框架管理器要求恢复模块状态，再正常重启手机。依据、命令范围和回归检查见 [重启实现说明](docs/lsposed-safe-mode.md)。

## 4.4 修复

- 推荐作用域补上系统界面插件；主页显示框架实际启用的两个作用域。
- 插件在独立进程或作为 SystemUI 的后续包加载时均注册流体云 Hook；独立插件进程不安装下拉背景等主进程 Hook。
- 兼容固件插件工厂的缓存 ClassLoader 路径，不再只监听新建加载器。
- 插件 UID 可读取配置，独立进程报告单独保存，避免干扰 SystemUI 配置确认。报告显示流体云注册接口、命中及参数。

## 功能

- 控制中心与通知中心共用一组背景模糊、混色颜色和强度设置。混色强度为 0% 时清除混色，关闭自定义后恢复系统参数。
- 自定义混色时，面板、通知条和横幅中的标准文字根据各自背景在黑白之间自适应，颜色变化以 160 毫秒灰阶过渡。计算包含混色透明度、面板与卡片叠加及局部纯色背景；半透明底层使用壁纸主色估算，壁纸配色变化后更新。开启、不可用及不可操作快捷开关保留系统文字配色。关闭对应混色后恢复系统文字。渐变背景、自绘文字和通知中的独立颜色 Span 暂不保证覆盖；横幅不叠加未显示面板的颜色估算；前台应用底图、原生材质、复杂壁纸及动画中的实际对比度仍需真机确认。
- 通知横幅独立调整模糊、背景混色颜色与强度，覆盖单层和前后多层原生混色。
- 控制中心磁贴与通知中心通知条分别保存材质设置，入口为“调节 → 控制中心磁贴”和“调节 → 通知中心 → 通知卡片”，各自独立调整模糊、混色颜色与透明度、圆角。快捷开关、媒体卡片与音量和亮度滑条底色也使用这一组设置，覆盖关闭状态的快捷开关、媒体卡片，以及滑条底色，包含模糊和无模糊路径；普通快捷开关的开启、不可用和不可操作状态保留系统配色；控制中心可调整尺寸的 2×1 磁贴与通知中心顶部 2×1 快捷卡片的整张背景使用共用材质，包含普通背景、主题过渡背景和背景重建，图标和文字状态由系统处理。振动 / 静音的三段式 2×1 磁贴也接入共用材质。自定义圆角使用与通知条相同的 0–64 dp 半径，所有尺寸磁贴、媒体 / 设备卡片和滑条共用相同实际半径，超出容器时才限制到短边一半；背景、裁剪、模糊和边缘高光使用相同的实际半径与边界，并通过原生 G2 平滑路径绘制；圆形、胶囊及普通圆角切换为自定义圆角时统一使用 G2 权重 3，背景与主题重建后继续生效，同步设备中心插件背景、视图裁剪、滑条内部填充、描边及按压高光，保留滑条原生按压放大比例。实现依据与验证范围见 [控制中心平滑圆角](docs/control-center-corners.md)。滑条进度填充保留系统颜色，便于区分状态与进度。透明度 0% 清除自定义背景混色，关闭后恢复系统背景。配置变更会刷新已创建的卡片和滑条。
- 通知条与控制中心磁贴各自使用独立的颜色、模糊和圆角参数，沿用相同的背景混色算法，清除原生多余混色层，覆盖原生多层混色和无模糊填色；悬浮横幅结束后恢复通知条自身的材质。磁贴与通知条均采用普通 alpha 叠色：最终颜色 = 背景 × (1 − 不透明度) + 所选颜色 × 不透明度；平台 Shader 使用 MIX，动态模糊与流体云使用框架原生 COLORMIX，静态模糊使用单次颜色遮罩；单层、多层 Shader 与软件填色回退统一透明度处理，避免重复叠色与重复动画衰减。整体面板和通知横幅也使用同一颜色含义。100% 为所选纯色，模糊独立控制背景细节。固件依据、公式及验证范围见 [卡片混色算法核对](docs/card-blending.md)。通知横幅也支持独立圆角，入口为“调节 → 通知横幅”。
- 调节首页按“控制与通知、状态与导航、声音”分组，入口摘要说明可调内容。控制与通知收纳下拉背景、控制中心磁贴和通知中心；通知中心再按通知列表与悬浮通知分组，提供通知卡片、列表布局和通知横幅。状态与导航收纳状态栏、流体云与手势条，声音提供音量面板。详情页统一使用卡片外分组标题和间距，区分尺寸、材质、色彩与显示内容。分类总览页直接展示入口，效果预览保留在具体调整页。进入与返回使用 320 毫秒双向滑动和淡入淡出，返回按钮和系统返回键按页面层级逐级返回，并保留一级列表滚动位置。
- 状态栏修改：入口为“调节 → 状态栏”，统一收纳布局与间距、时钟修改、图标样式和图标显示。布局可分别设置左、右边距（0–64dp），中间额外留白（0–80dp）分配给左右内容内侧，保留原生挖孔占位和边缘挖孔避让。长时钟可开启自动横向压缩，按实际可用宽度显示完整内容，空间恢复后还原；同时约束 C17 秒数时钟的固定测量宽度。时钟支持跟随系统 / 12 / 24 小时、秒数、日期、星期、字号与加粗，使用原生秒数刷新和息屏机制，仅修改桌面与应用顶部时钟。普通参数实时应用，关闭自定义或总开关后恢复原值；新功能默认关闭。进入图标或时钟等子页后，返回键先回到状态栏菜单。配置导出与旧版迁移、布局恢复及秒数时钟的合成检查已覆盖，手机显示仍需真机确认。
- 状态栏图标替换：入口为“调节 → 状态栏 → 图标样式”，可选系统默认或 iOS 风格。图标、Wi-Fi、横向与竖向电池、蓝牙电池均直接使用用户提供的 PUI ColorOS 17 包内原始 XML，不再重绘或使用第一包素材；包内未覆盖的状态保留系统图标。图标放大 12%，相邻图标额外增加约 2dp 间距，横向电池尺寸为 28 × 17dp，百分比按电池主体居中，自动适配一位、两位和三位数字；状态栏在系统原高度上增加 4dp，保留挖孔与旋转判断，并同步窗口和应用避让区域。隐藏 Wi-Fi / 信号角标、上下行箭头及文字型 5G；堆叠主卡信号柱、副卡圆点沿用 C17 原资源。电量、充电与双卡排列由系统管理。修改样式或总开关后需通过右上角“重启系统界面”应用。锁屏、下拉共用的资源可能同步变化，最终显示仍需真机确认。
- 手势条：入口为“调节 → 手势条”，可调整长度（40–320 dp）、粗细（1–16 dp）和距底部高度（0–32 dp，限制在原生导航区域内）；手势条材质内统一设置模糊、混色、圆角及亮暗颜色，并使用系统背景明暗采样自动换色，关闭自动后跟随系统浅色 / 深色模式；尺寸、材质及恢复机制见 [手势条外观](docs/gesture-bar.md)。另提供独立的“隐藏手势条”和“取消底部抬高”开关。取消抬高清除全面屏手势导航向应用上报的底部占位，让应用内容延伸到底边；保留导航窗口尺寸及手势检测区域。三键导航和系统强制显示的辅助导航按钮保留原占位；关闭后实时恢复系统参数。输入法和应用自行添加的底部留白仍由各自控制。已核对 C17 接口并通过合成回归，实际显示待真机验证。
- 状态栏图标独立隐藏：蓝牙、闹钟、静音 / 振动、勿扰、VPN、个人热点、旋转锁定、耳机、NFC、高性能模式。入口为“调节 → 状态栏 → 图标显示”，默认全部跟随系统，支持一键恢复。自动保存后通过配置监听刷新；仅影响显示，不会关闭对应功能。系统共用的锁屏、下拉图标也可能受影响。
- 流体云按“胶囊状态、卡片状态”分别保存模糊、混色及圆角，胶囊另有高度调节。插件中的同一形态共用设置。锁屏原生流体云另有“锁屏样式”入口，直接提供独立模糊/混色自定义，关闭对应开关恢复系统值；“应用取色遮罩”仅保留 0–200% 自定义强度调节，0% 即关闭、100% 为系统强度，单色、渐变均从原始颜色重新计算，关闭流体云外观后恢复原生值。具体接口与验证范围见 [锁屏流体云与应用取色遮罩](docs/cloud-lockscreen.md)。自定义卡片混色时去除额外渐变层，并在渐变重建后继续抑制叠色；圆角同时覆盖原生模糊、渐变、填色与通知内容裁剪。配置同步后刷新已有背景，关闭自定义时恢复系统参数。
- 主页、调节、设置三页采用带 Miuix 图标的悬浮导航；二级页面隐藏底部导航，提供更多调节空间。顶部使用 Miuix `SmallTopAppBar`，页面按顶栏实际高度留白；返回、重启、导航及分类入口图标统一使用 Miuix Icons 0.9.0；左上角返回、右上角重启系统界面均使用 LiquidButton。
- 支持预测返回：应用内返回时，页面随左右边缘手势缩放、平移和圆角变化；完成手势才返回上一级，取消后平滑复原。主页交由系统处理返回桌面的预测动画。
- 滑块在组件内保留连续浮点手势值，松手后提交；开关和颜色确认后自动保存。改过的滑块、开关、颜色和外观选项提供“回退”，返回本次编辑前的值。
- 设置首页提供界面外观、配置管理和关于入口；明暗模式、配色、玻璃参数、JSON 导入导出和恢复默认均收纳到二级页面。主页运行报告也使用独立二级页面，支持刷新和复制。使用 `thunder.settings` 配置格式。
- 通知横幅页提供“返回桌面并测试横幅”：先检查通知权限及渠道，自动将应用切至后台，界面停止显示约 1 秒后发送真实测试通知，避免 ColorOS 抑制前台应用自身的横幅。首次发送请求通知权限，点击通知可返回，通知在 15 秒后自动移除。横幅是否显示仍受系统通知渠道、勿扰模式和提醒频率限制。
- 框架连接、配置同步与 SystemUI 运行报告，以及运行中配置版本的读取确认。

这是独立 APK，运行不依赖 KSU 主题包或挂载脚本。状态栏样式将 PUI ColorOS 17 包内原始图标与电池、信号资源内置到 APK；运行时不依赖原主题包安装或挂载。

## 安装使用

1. 安装签名后的 thunder APK。同包名、同签名可以覆盖升级，已有配置会保留。保留原有独立 App 与桌面图标，可直接打开原来的 Miuix / Liquid Glass 配置界面。
2. 在 LSPosed 中启用模块，勾选 **设置 / com.android.settings**、**系统界面 / com.android.systemui** 和 **系统界面插件 / com.oplus.systemui.plugins**。升级不会自动授权新增作用域；旧用户也需要手动补勾“设置”。
3. 正常重启手机加载 Hook，然后打开桌面的 **thunder** App；也可进入 **系统设置 → thunder**（位于设置列表末尾）。首次安装必须经过 LSPosed 启用与作用域授权，仅安装 APK 不会自动注入系统设置。
4. 直接在系统设置内调整下拉背景、磁贴、通知、音量、流体云、状态栏与手势条。页面由系统的 `SubSettings` 与 `COUIPreferenceFragment` 承载，开关、选择器、数值输入及颜色选择均复用该固件的原生组件与 COUI 对话框，跟随系统设置的主题与返回导航。
5. 改动自动保存并通过已有 API 102 配置链路同步。主页“模块状态”可点按刷新。进入“配置与维护”可复制配置、从 JSON 文件导入、重置，或请求 Root 重启系统界面。图标样式切换需要重启 SystemUI，其他缓存参数可先重新展开对应界面。
6. 系统设置页只负责显示与提交参数，配置文件、导入校验、版本号、Root 请求及框架同步都由模块自身进程处理。未加载配置时控件不可修改；读取失败会显示重试入口。控件不把模块参数写入系统设置自己的偏好文件。

原有独立 App 及其完整界面保留，可从 **桌面 → thunder** 或 **LSPosed → thunder → 模块设置** 打开。独立 App 继续使用原来的 Miuix / Liquid Glass 界面，系统设置集成仅作为额外入口。原有实时预览、文件导入导出、通知横幅测试、Root 验证及运行报告逻辑保留。系统设置内使用系统主题，独立 App 的配色与玻璃参数仍只影响 App 本身。若当前固件缺少已核对的 COUI 或设置接口，模块会记录错误，不将第三方仿制界面当作系统设置注入。实现和验收边界见 [系统设置集成](docs/system-settings-integration.md)。

设置页的界面配色只影响 thunder 自身。修改系统下拉背景需要在“调节”页启用对应选项。报告命中说明相关代码路径已执行，并不等于视觉效果已经通过真机验证。

图标样式通过 `Resources.getDrawableForDensity`、`TypedArray.getDrawableForDensity` 与静态矢量 `Resources.getXml` 提供编译后的原生资源；PUI C17 尺寸接入现有 Resources / TypedArray / getValue 入口；限定的 C17 网络文字绑定隐藏 5G，SystemBarUtils 高度入口统一增加 4dp。运行报告中的 `status-bar-ios-resource-drawable` / `status-bar-ios-resource-xml` 表示加载命中，`restart-required=true` 表示当前进程样式与已选配置不同。实现与验证边界见 [状态栏资源方案](docs/status-icons-rendering.md)。

状态栏使用导出 C17 固件中的 `StatusBarIconControllerImpl.mIconHideList` 和原生图标重建流程，合并系统已有的隐藏项，不写入系统的 `icon_blacklist`。关闭隐藏开关表示恢复为跟随系统，不会强制显示系统原先隐藏的图标。运行报告中的 `status-bar-icons` 记录已应用的图标槽位。配置导出格式为 v19，支持导入 v3 至 v18；旧配置的手势条外观默认关闭；旧配置中的独立音量按钮参数会统一跟随音量条；旧配置中的应用过渡开关会被忽略；旧配置的图标样式默认为系统默认。旧配置的流体云参数会迁移到胶囊和卡片两种形态，迁移后独立调节；v8 至 v11 的共用卡片配置会作为磁贴与通知条各自的初始值，之后独立保存、调节和恢复系统材质；v7 的独立磁贴与通知条配置分别保留。

## 界面配色

“设置 → 界面外观 → 界面配色”提供自定义、壁纸取色和自选取色。Monet 使用 Miuix 0.9.0 的 `ThemeController`：壁纸取色跟随系统动态配色，自选取色根据种子色生成完整配色。明暗模式独立选择，卡片、文字、导航和 Liquid 控件共用主题颜色。原有配置保留自定义强调色与底色，切换 Monet 不会覆盖它们。

主页直接展示效果总开关、LSPosed 与作用域状态、Root 验证和运行报告入口，不设快捷调节入口。开启自定义开关后显示对应参数；模糊、边距、尺寸和百分比保留玻璃滑块，点击数值行可精确输入整数，超出范围或无效输入不能保存。时钟字号、手势条粗细和界面圆角改用 MIUIx 数字滚轮，确认后提交。主题、配色来源、时间制式、日期格式、图标方案、音量动画与展开方式、手势条颜色切换依据使用设置行和带说明的 MIUIx 单选列表。具体外观调整页顶部提供实时效果预览，可在“当前 / 系统”间对照并点击放大；覆盖通知与控制中心、流体云四页、音量、状态栏和手势条，界面外观使用真实主题与玻璃组件。预览直接读取待保存参数，关闭模块或流体云总开关时显示系统示例；应用取色遮罩可切换音乐 / 出行示例色。预览读取当前设备的系统图标与原生尺寸，按 ColorOS 17 控制中心、通知、流体云和音量面板布局绘制，使用 PUI 主题壁纸、局部背景模糊及固定样例内容。iOS 图标沿用原始 PUI 资源；未替换的旋转锁定、热点等图标读取系统原图，缺少资源时安全跳过。音量预览可切换收起 / 展开；实际动态材质仍受设备壁纸、应用与系统影响。状态栏、流体云、通知中心等分类总览，以及配置管理、关于和运行报告不显示外观预览。设置行、颜色入口和回退按钮的按压反馈按圆角裁剪，玻璃按钮的背景与高亮使用相同形状，文字按钮随内容增高。材质取色弹窗提供“色板 / 调色 / HEX”三种方式，不透明的主题颜色提供“调色 / HEX”：色板复用 MIUIx ColorPalette，调色保留 HSV 通道，HEX 提供带校验的 MIUIx 文本输入；确认后才保存。颜色预览单独裁剪，确认按钮固定在滚动区域外；不透明颜色隐藏透明度滑条。参数仍自动保存，操作结果以短暂提示展示。

## GitHub Actions 与发布

[构建工作流](../../actions/workflows/android.yml) 按以下条件运行：

- 推送或合并到 `main`：只有 `app/build.gradle.kts` 改动时才启动工作流，再比较本次推送前后的 `versionName` 和 `versionCode`；任一版本号变化才构建，其他 Gradle 配置变化会跳过构建。
- Pull Request：不自动构建。
- 推送 `v*` 标签：构建并签名发布，不受文件路径或版本号变化检测限制。
- 手动运行：始终构建；选择版本标签运行时还会签名发布。

构建执行处理器检查、安全模式回归与配置监听检查、单元测试、Lint 和 Release 构建，保留未签名 APK 及检查报告。普通分支构建不使用发布密钥。一次推送包含多个提交时，版本比较覆盖整个推送，而非仅比较最后一个提交。

tag（标签）用于给某个提交固定版本名，例如 `v4.6`，方便定位发布源码和回退；本仓库还用它作为正式签名和 GitHub Release 发布的触发入口。只修改版本号并推送 `main` 会生成未签名构建，推送标签后才会生成可安装的正式发布包，因此版本提交和标签发布各会构建一次。

发布步骤：

1. 更新 `app/build.gradle.kts` 中的 `versionName` 与递增的 `versionCode`，提交并推送。`versionName` 不带 `v` 前缀，使用 `主版本.次版本` 或 `主版本.次版本.补丁版本` 格式，例如 `"8.0"`。
2. 在版本更新提交上创建 `v` + `versionName` 的版本标签，例如 `git tag v8.0`，再执行 `git push origin v8.0`。标签必须与 APK 版本完全一致，`v8` 不能替代 `v8.0`；标签指向旧提交时，只更新 `main` 或重新运行旧标签的工作流不会更新其 APK 版本。
3. 工作流核对包名、APK 版本与标签，全部检查通过后使用正式密钥签名、验证签名及 16 KB 对齐，并发布 [GitHub Release](../../releases)，包含 APK 和 SHA-256 校验文件。

也可以在已有标签上手动运行工作流。带 `-` 的版本标记为预发布；已发布的版本不覆盖，应递增版本后发布。发布失败留下的草稿可以通过重新运行工作流继续上传并发布。

仓库 Actions Secrets 需要配置：

| 名称 | 内容 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | thunder 发布 keystore 的 Base64 内容 |
| `ANDROID_KEYSTORE_PASSWORD` | keystore 密码 |
| `ANDROID_KEY_ALIAS` | 发布密钥别名 |
| `ANDROID_KEY_PASSWORD` | 发布密钥密码 |

仓库变量 `ANDROID_SIGNING_CERT_SHA256` 保存签名证书的 SHA-256 指纹（小写、无冒号），工作流用它核对签名身份。已为本仓库配置 thunder 专用发布密钥；请保管密钥备份，后续版本需要使用同一密钥才能覆盖升级。

## 目录

```text
app/                 Android 应用、Hook、配置和单元测试
gradle/              Gradle Wrapper
scripts/             可独立执行的检查脚本
.github/workflows/   自动构建、签名与 Release 发布
```

本地 `archive/` 保存原始模块包、采集文件及历史产物，`.local/` 保存工具链、签名和分析资料，`dist/` 保存签名构建结果。这些目录均被 Git 忽略。

Kyant0 的四类 Liquid 组件使用官方 Catalog 源码，其余界面组件使用 Miuix；预览切换、卡片、弹窗和进度展示同样复用库组件。UI 构建约束见 [AGENTS.md](AGENTS.md)。详细来源与改动说明见 [THIRD_PARTY.md](THIRD_PARTY.md)，许可证随 APK 打包在 `app/src/main/assets/licenses/` 中。
