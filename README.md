# thunder

适用于 ColorOS 17 的独立 LSPosed 模块，调整 SystemUI 的下拉背景、通知横幅、通知边距、流体云外观与状态栏图标显示。设置自动保存，改动的组件旁可回退。

当前版本 **6.0 / versionCode 11**，应用包名及源码命名空间统一为 `io.github.baishangui.thunder`，配置格式为 `thunder.settings`。

## 环境要求

- Android 17 / SDK 37，目标适配 ColorOS 17.0.0.104（CN01）的 SystemUI。
- 支持 **libxposed API 102** 的 LSPosed。管理器版本号不能替代实际连接检查，以应用主页的连接状态和运行报告为准。
- 外观效果通过 SystemUI 进程中的 Hook 实现；应用内同步配置无需 Root 授权。

目前没有连接真机验证注入、视觉效果或性能；其他 ColorOS 版本的内部接口可能不同。流体云的原生背景模糊依赖设备固件提供的 ViewRootManager 后端。

## 音量面板

“调节 → 音量 → 音量面板”支持音量条长宽、圆角、背景混色与模糊，以及原生按钮大小和材质。开启“跟随音量条展开”后，继续使用系统的音量行、标题、设置按钮、弹簧动画与收起流程，将音量行终点和背景限制在当前音量条附近的小面板内。安装更新后需重启系统界面；参数随后实时同步。已加入原生流程保留与几何回归，动画观感和触摸手感仍需目标真机验证。实现与验收见 [音量面板说明](docs/volume-panel.md)。

## 配置实时应用与系统界面重启

- 修改参数自动保存，并通过 API 102 远程配置监听实时应用。SystemUI 和独立插件进程在工作线程读取完整快照，合并同次提交的通知，并刷新现有背景代理与状态栏图标。已有视图缓存的布局参数可能需要重新展开对应界面。
- 右上角提供“重启系统界面”：先保存并确认远程配置写入成功，再申请 Root，仅重启 `com.android.systemui`。自动调参不执行重启，也无需 Root。
- 重启先发送 TERM；若原进程在 3 秒内未退出，只向仍存活的原 PID 补一次 KILL，随后等待新进程。不会重复结束新进程，不会重启手机或 Zygote。流程在后台继续，阻止并行请求，并持久记录 60 秒操作间隔；Root 授权超过请求有效期不会执行过期重启。
- 只有新 PID、本版 Hook、当前或更新配置版本以及本次操作之后的报告全部匹配，才显示重启确认成功。拒绝授权、未找到进程、启动超时和未收到 Hook 回报分别提示，不会自动重试。
- LSPosed 2.2.1 (7912) 的历史日志显示手动结束 SystemUI 会累计退出保护计数；限频和 TERM 优先不能保证消除计数。若已进入安全模式，需要先按框架管理器要求恢复模块状态，再尝试重启系统界面。此流程尚待同版本框架与真机验证。

## 4.4 修复

- 推荐作用域补上系统界面插件；主页显示框架实际启用的两个作用域。
- 插件在独立进程或作为 SystemUI 的后续包加载时均注册流体云 Hook；独立插件进程不安装下拉背景等主进程 Hook。
- 兼容固件插件工厂的缓存 ClassLoader 路径，不再只监听新建加载器。
- 插件 UID 可读取配置，独立进程报告单独保存，避免干扰 SystemUI 配置确认。报告显示流体云注册接口、命中及参数。

## 功能

- 控制中心与通知中心共用一组背景模糊、混色颜色和强度设置。混色强度为 0% 时清除混色，关闭自定义后恢复系统参数。
- 自定义混色时，面板、通知条和横幅中的标准文字根据各自背景在黑白之间自适应，颜色变化以 160 毫秒灰阶过渡。计算包含混色透明度、面板与卡片叠加及局部纯色背景；半透明底层使用壁纸主色估算，壁纸配色变化后更新。开启、不可用及不可操作快捷开关保留系统文字配色。关闭对应混色后恢复系统文字。渐变背景、自绘文字和通知中的独立颜色 Span 暂不保证覆盖；横幅不叠加未显示面板的颜色估算；前台应用底图、原生材质、复杂壁纸及动画中的实际对比度仍需真机确认。
- 通知横幅独立调整模糊、背景混色颜色与强度，覆盖单层和前后多层原生混色。
- 控制中心磁贴与通知中心通知条分别保存材质设置，入口为“调节 → 控制中心磁贴”和“调节 → 通知中心通知条”，各自独立调整模糊、混色颜色与透明度、圆角。快捷开关、媒体卡片与音量和亮度滑条底色也使用这一组设置，覆盖关闭状态的快捷开关、媒体卡片，以及滑条底色，包含模糊和无模糊路径；普通快捷开关的开启、不可用和不可操作状态保留系统配色；控制中心可调整尺寸的 2×1 磁贴与通知中心顶部 2×1 快捷卡片的整张背景使用共用材质，包含普通背景、主题过渡背景和背景重建，图标和文字状态由系统处理。振动 / 静音的三段式 2×1 磁贴也接入共用材质。自定义圆角使用 0–64 程度，按各背景短边缩放，1×1 磁贴在 64 时才成为圆形；背景、裁剪、模糊和边缘高光使用相同的实际半径与边界，并通过原生 G2 平滑路径绘制；圆形、胶囊及普通圆角切换为自定义圆角时补齐平滑参数，同步设备中心插件背景、视图裁剪、滑条内部填充、描边及按压高光，保留滑条原生按压放大比例。实现依据与验证范围见 [控制中心平滑圆角](docs/control-center-corners.md)。滑条进度填充保留系统颜色，便于区分状态与进度。透明度 0% 清除自定义背景混色，关闭后恢复系统背景。配置变更会刷新已创建的卡片和滑条。
- 通知条与控制中心磁贴各自使用独立的颜色、模糊和圆角参数，沿用相同的背景混色算法，清除原生多余混色层，覆盖原生多层混色和无模糊填色；悬浮横幅结束后恢复通知条自身的材质。磁贴与通知条均采用普通 alpha 叠色：最终颜色 = 背景 × (1 − 不透明度) + 所选颜色 × 不透明度；平台 Shader 使用 MIX，动态模糊与流体云使用框架原生 COLORMIX，静态模糊使用单次颜色遮罩；单层、多层 Shader 与软件填色回退统一透明度处理，避免重复叠色与重复动画衰减。整体面板和通知横幅也使用同一颜色含义。100% 为所选纯色，模糊独立控制背景细节。固件依据、公式及验证范围见 [卡片混色算法核对](docs/card-blending.md)。通知横幅也支持独立圆角，入口为“调节 → 通知横幅”。
- 调节首页按“通控中心、流体云、状态栏”分组，只显示分类入口和当前状态摘要。整体背景、控制中心磁贴、通知中心通知条、通知布局、通知横幅、胶囊状态、卡片状态及图标显示均点击进入独立二级页面；通知布局提供列表左右边距调节，适配单栏、双栏和分屏资源。进入与返回二级页面使用 320 毫秒双向滑动和淡入淡出，标题与底部导航同步过渡；切换一级页面也有方向过渡。返回按钮和系统返回键优先返回分类页，并保留一级列表滚动位置。
- 状态栏图标替换：入口为“调节 → 状态栏 → 图标样式”，可选系统默认或 iOS 风格。按 C17 固件核对 298 个状态资源，覆盖蓝牙、静音、振动、NFC、VPN、投屏、网络制式、漫游、无服务与网络异常等状态。图形按可见范围决定容器宽度，统一 20 dp 高度及 3 dp 目标可见间距；信号、网络标记和数据箭头分开排布，消除原生额外留白与重复缩放。时间最大 17 dp，按可用宽高适配并清除秒数宽度缓存。横向、竖向、圆形及旧版电池统一替换为 iOS 16 风格实心百分比电池，保留系统配色、电量、充电和反向充电状态。双卡可选分开或堆叠，分别显示真实强度。关闭后恢复原始图形、布局、字体、双卡模式和电池样式，不改变系统偏好。通知应用标识保留；共用的锁屏、下拉状态图标可能同步变化。预览见 [图标设计](docs/status-icons-ios.png)，尚未连接真机验证最终像素效果。
- 手势条：入口为“调节 → 手势导航 → 手势条”，提供独立的“隐藏手势条”和“取消底部抬高”开关。取消抬高清除全面屏手势导航向应用上报的底部占位，让应用内容延伸到底边；保留导航窗口尺寸及手势检测区域。三键导航和系统强制显示的辅助导航按钮保留原占位；关闭后实时恢复系统参数。输入法和应用自行添加的底部留白仍由各自控制。已核对 C17 接口并通过合成回归，实际显示待真机验证。
- 状态栏图标独立隐藏：蓝牙、闹钟、静音 / 振动、勿扰、VPN、个人热点、旋转锁定、耳机、NFC、高性能模式。入口为“调节 → 图标显示”，默认全部跟随系统，支持一键恢复。自动保存后通过配置监听刷新；仅影响显示，不会关闭对应功能。系统共用的锁屏、下拉图标也可能受影响。
- 流体云按“胶囊状态、卡片状态”分别保存模糊、混色及圆角，胶囊另有高度调节。状态栏与锁屏的同一形态共用设置。自定义卡片混色时去除额外渐变层，并在渐变重建后继续抑制叠色；圆角同时覆盖原生模糊、渐变、填色与通知内容裁剪。配置同步后刷新已有背景，关闭自定义时恢复系统参数。
- 主页、调节、设置三页采用带 Miuix 图标的悬浮导航；二级页面隐藏底部导航，提供更多调节空间。顶部使用 Kyant0 教程中的透明遮罩渐进模糊，返回、重启、导航及分类入口图标统一使用 Miuix Icons 0.9.0；左上角返回、右上角重启系统界面均使用 LiquidButton。
- 支持预测返回：应用内返回时，页面随左右边缘手势缩放、平移和圆角变化；完成手势才返回上一级，取消后平滑复原。主页交由系统处理返回桌面的预测动画。
- 滑块在组件内保留连续浮点手势值，松手后提交；开关和颜色确认后自动保存。改过的滑块、开关、颜色和外观选项提供“回退”，返回本次编辑前的值。
- 设置首页提供界面外观、配置管理和关于入口；明暗模式、配色、玻璃参数、JSON 导入导出和恢复默认均收纳到二级页面。主页运行报告也使用独立二级页面，支持刷新和复制。使用 `thunder.settings` 配置格式。
- 通知横幅页提供“返回桌面并测试横幅”：先检查通知权限及渠道，自动将应用切至后台，界面停止显示约 1 秒后发送真实测试通知，避免 ColorOS 抑制前台应用自身的横幅。首次发送请求通知权限，点击通知可返回，通知在 15 秒后自动移除。横幅是否显示仍受系统通知渠道、勿扰模式和提醒频率限制。
- 框架连接、配置同步与 SystemUI 运行报告，以及运行中配置版本的读取确认。

这是独立 APK，运行不依赖 KSU 主题包或挂载脚本。状态栏样式使用本项目重新绘制的矢量图标，不依赖原主题包资源。

## 安装使用

1. 从 GitHub Releases 安装签名后的 thunder APK。新包名会作为独立应用安装；首次安装需重新启用模块并设置作用域。卸载旧包前先在 LSPosed 中停用，避免两个模块同时修改 SystemUI。后续版本可使用同一包名和签名覆盖升级。
2. 在 LSPosed 中启用模块，作用域同时勾选 **系统界面 / com.android.systemui** 和 **系统界面插件 / com.oplus.systemui.plugins**。从 4.3 升级也需检查并手动勾选新增作用域，升级 APK 不会自动启用它。主页会读取框架实际作用域，提示缺少哪一项。
3. 首次安装、更新作用域或升级模块后，打开应用等待框架连接，再点击右上角“重启系统界面”加载 Hook。
4. 在“调节”页开启需要的功能。交互会自动保存并同步，不再需要手动点击保存。
5. 普通修改会实时应用；缓存参数未刷新时可先重新展开对应界面，或点击右上角“重启系统界面”。重启操作需要 Root，应用会等待新进程与本版 Hook 的配置确认；若 LSPosed 已进入安全模式，先按框架管理器要求恢复模块状态。
6. 执行下拉或触发通知横幅后，在主页刷新状态、查看或复制运行报告。

设置页的界面配色只影响 thunder 自身。修改系统下拉背景需要在“调节”页启用对应选项。报告命中说明相关代码路径已执行，并不等于视觉效果已经通过真机验证。

图标样式通过 `StatusBarIconView.getIcon`、状态栏 ImageView 的资源 / Drawable 绑定、原生测量、动态 SignalDrawable 与电池 binder / draw 接入。保留原始 Drawable、布局和电池模型以便实时恢复。运行报告的 `status-bar-ios-*` 命中记录实际绘制路径。

状态栏使用导出 C17 固件中的 `StatusBarIconControllerImpl.mIconHideList` 和原生图标重建流程，合并系统已有的隐藏项，不写入系统的 `icon_blacklist`。关闭隐藏开关表示恢复为跟随系统，不会强制显示系统原先隐藏的图标。运行报告中的 `status-bar-icons` 记录已应用的图标槽位。配置导出格式为 v14，支持导入 v3 至 v13；旧配置中的应用过渡开关会被忽略；旧配置的图标样式默认为系统默认。旧配置的流体云参数会迁移到胶囊和卡片两种形态，迁移后独立调节；v8 至 v11 的共用卡片配置会作为磁贴与通知条各自的初始值，之后独立保存、调节和恢复系统材质；v7 的独立磁贴与通知条配置分别保留。

## 构建

使用 JDK 17、Android SDK Platform 37（本地 SDK 目录通常为 `platforms/android-37.0`）和 Build Tools 35.0.0。项目提供 Gradle 8.13 Wrapper，并锁定依赖版本。

在 `local.properties` 中设置本机 SDK 路径，或配置 `ANDROID_HOME`，然后执行：

```sh
./gradlew :app:testReleaseUnitTest :app:lintRelease :app:assembleRelease
python3 scripts/check_systemui_restart.py
python3 scripts/check_live_settings.py
python3 scripts/check_effects.py
```

Windows 使用 `gradlew.bat`。本地构建输出为 `app/build/outputs/apk/release/app-release-unsigned.apk`，需签名后安装。仓库不包含发布私钥，正式安装包由 GitHub Actions 签名并发布。

重启回归检查使用一次性测试进程验证 TERM、单次 KILL 兜底、Root 拒绝、无目标进程、非法 PID、新进程超时及请求过期；自动调参仍只走配置监听通道。配置监听检查覆盖完整快照、重复通知、读取失败及恢复。效果检查用合成的 Android / Oplus 替身执行实际 Java 处理器，覆盖展开进度、状态恢复、流体云原生接口、多层背景圆角及锁屏共用背景的重建、横幅多层混色、卡片原生混色与遮罩、无模糊填色、配置恢复及异常后的状态还原；新增检查覆盖磁贴与通知条独立材质、通知中心顶部 2×1 背景状态与重建、不同原生模式统一混色、旧版共用配置迁移与独立配置保留、通知条与横幅切换、四角参数、分组裁剪、胶囊与卡片独立配置、无模糊胶囊混色、渐变重建及关闭恢复。状态栏替换检查覆盖通知图标与包名隔离、信号视图范围、原始尺寸与颜色、样式关闭恢复、实时刷新、电池百分比及充电标记。图标矢量预览见 [预览图](docs/status-icons-ios.svg)，可通过 `python3 scripts/render_status_icons.py` 从资源重新生成；来源与参考图见 [来源说明](docs/status-icons-sources.md)。可用 `python3 scripts/check_effects.py --only IosStatusBarCheck` 单独检查图标、文字居中、尺寸恢复和双卡切换。不包含采集固件，也不验证手机渲染。

主要依赖：AGP 8.13.2、Kotlin 2.3.20、Compose 1.10.3、Kyant0 Backdrop 1.0.6、Shapes 1.2.0、Miuix UI / Icons 0.9.0，以及 libxposed API / Service 102.0.0。

## GitHub Actions 与发布

[构建工作流](../../actions/workflows/android.yml) 按以下条件运行：

- 推送或合并到 `main`：只有 `app/build.gradle.kts` 改动时才启动工作流，再比较本次推送前后的 `versionName` 和 `versionCode`；任一版本号变化才构建，其他 Gradle 配置变化会跳过构建。
- Pull Request：不自动构建。
- 推送 `v*` 标签：构建并签名发布，不受文件路径或版本号变化检测限制。
- 手动运行：始终构建；选择版本标签运行时还会签名发布。

构建执行处理器检查、安全模式回归与配置监听检查、单元测试、Lint 和 Release 构建，保留未签名 APK 及检查报告。普通分支构建不使用发布密钥。一次推送包含多个提交时，版本比较覆盖整个推送，而非仅比较最后一个提交。

tag（标签）用于给某个提交固定版本名，例如 `v4.6`，方便定位发布源码和回退；本仓库还用它作为正式签名和 GitHub Release 发布的触发入口。只修改版本号并推送 `main` 会生成未签名构建，推送标签后才会生成可安装的正式发布包，因此版本提交和标签发布各会构建一次。

发布步骤：

1. 更新 `app/build.gradle.kts` 中的 `versionName` 与递增的 `versionCode`，提交并推送。`versionName` 不带 `v` 前缀，例如 `"5.0"`。
2. 创建 `v` + `versionName` 的版本标签，例如 `git tag v5.0`，再执行 `git push origin v5.0`。
3. 工作流核对包名、APK 版本与标签，全部检查通过后使用正式密钥签名、验证签名及 16 KB 对齐，并发布 [GitHub Release](../../releases)，包含 APK 和 SHA-256 校验文件。

也可以在已有标签上手动运行工作流。带 `-` 的版本标记为预发布；已发布的版本不覆盖，应递增版本后发布。发布失败留下的草稿可以通过重新运行工作流继续上传并发布。

仓库 Actions Secrets 需要配置：

| 名称 | 内容 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | thunder 发布 keystore 的 Base64 内容 |
| `ANDROID_KEYSTORE_PASSWORD` | keystore 密码 |
| `ANDROID_KEY_ALIAS` | 发布密钥别名 |
| `ANDROID_KEY_PASSWORD` | 发布密钥密码 |

仓库变量 `ANDROID_SIGNING_CERT_SHA256` 保存签名证书的 SHA-256 指纹（小写、无冒号），工作流用它核对签名身份。已为本仓库配置 thunder 专用发布密钥；请保管密钥备份，后续版本需要使用同一密钥才能覆盖升级。

## 目录

```text
app/                 Android 应用、Hook、配置和单元测试
gradle/              Gradle Wrapper
scripts/             可独立执行的检查脚本
.github/workflows/   自动构建、签名与 Release 发布
THIRD_PARTY.md       第三方组件来源与许可
```

本地 `archive/` 保存原始模块包、采集文件及历史产物，`.local/` 保存工具链、签名和分析资料，`dist/` 保存签名构建结果。这些目录均被 Git 忽略。

Kyant0 的四类 Liquid 组件使用官方 Catalog 源码，其余界面组件使用 Miuix。详细来源与改动说明见 [THIRD_PARTY.md](THIRD_PARTY.md)，许可证随 APK 打包在 `app/src/main/assets/licenses/` 中。
