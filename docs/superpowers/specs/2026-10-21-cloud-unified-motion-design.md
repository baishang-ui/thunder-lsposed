# 流体云统一对象：动画、胶囊样式与原生交互迁移

日期：2026-10-21。状态：用户已确认“按推荐方案完整执行”，进入实现与验收。

## 目标与边界

保留已经完成的架构：胶囊和卡片是同一个持久视觉对象，由独立于状态栏的窗口承载。补齐胶囊与卡片双向形变、胶囊样式、前台程序进入流体云的衔接动画，以及旧版原生流体云的全部适用交互。

本次修改 SystemUI 宿主 Hook，不以 MIUIx / Liquid Glass 替换宿主控件。若需要调整模块设置页，独立 App 继续使用项目现有 MIUIx 与官方 Liquid Glass 封装；系统设置入口沿用原生 COUI schema。

通知中心、锁屏和 AOD 的既有专用逻辑保持原有职责，但进入这些场景时必须正确退出或移交当前浮层。不得留下浮层、触摸区域、回调或错误透明度。保留其他未提交工作。

## 方案比较

| 方案 | 优点 | 代价与适用性 |
| --- | --- | --- |
| A：保留统一视觉对象，补齐会话、内容/交互适配、连续运动 | 延续现有结构；原生业务、SDK 和应用跳转继续工作；可逐项回归 | 必须认真补齐根容器转发、可访问性和真实窗口测试。推荐 |
| B：将原生内容 View 移入独立窗口，接管父子结构 | 可利用真实子 View 的绘制和命中 | 破坏 SDK 原有 parent、挂载、布局、生命周期和根容器手势假设，固件兼容代价大 |
| C：继续增加分段 Animator 和 alpha 交接补丁 | 初始改动少 | 入场、更新、反向、旧手势仍分散；每帧窗口重布局问题仍存在，难以满足完整目标 |

采用 A。只接管视觉形态和独立浮层的输入适配，宿主状态机继续决定业务事件。

## 会话和状态

会话在胶囊内容首次有效且完成布局时创建，不依赖用户先展开卡片。已有显示中的胶囊也能在启用功能后接入。

状态至少表达：隐藏、进入、胶囊、展开中、卡片、收起中、退出/移交。服务标识、目标内容版本、当前显示的几何与速度、会话代次必须分开保存。旧回调只能清理它所属的代次。

同一会话始终保留同一个 Body。更换内容、mini/普通胶囊切换、宽度变化、胶囊展开和收起不得重新 add/remove Body。真正没有内容、禁用、容器销毁或退出该显示场景时才释放。

原生容器可继续提供业务信息、布局测量、原生事件和 SDK 内容；独立对象的屏幕坐标、轮廓及实际触摸区域由自己的视觉状态决定。不得把动画中的瞬时原生宽度误当稳态目标宽度，也不得缓存一次触摸的旧锚点后永久使用。

## 胶囊与卡片的运动

1. 位置、宽度、高度和圆角连续变化，内容透明度单独计算。展开时胶囊内容在前段退出，卡片内容在空间足够后进入；收起反向处理，终点不出现空胶囊。
2. 使用可重定向的阻尼弹簧或等价连续运动模型。中途反向继承当前呈现几何与速度，不能重新从 0 开始，也不能先跳到原生端点。
3. 回弹值映射阻尼/超调，限制尺寸和圆角始终合法。0 表示关闭超调，保留平滑停稳；正值提供一次主要轻回弹，避免多次抖动。位置、几何和内容 alpha 使用各自合法范围，alpha 不因几何超调反复切换。
4. 延续现有时长、曲线、回弹选项及配置兼容性。用户已保存值保持不变；真机视觉调参使用明确记录的轻回弹测试档，测试后恢复基线，除非用户要求保存新档。
5. 原生 Animator 身份、start/cancel/end、挂载、条件计时器和业务完成回调保留。视觉完成与原生结束分开处理；旧收起的隐藏请求不能移除新展开。
6. 系统关闭动画时直接收敛到目标，无重复出现、浮层残留或隐形触摸区域。

## 前台进入流体云的衔接

固件入口已经核实：`animatorscenes.e` 对应 `APP_TO_CAPSULE`，`f` 对应 `APP_TO_CAPSULE_WITH_NONE`，`h` 对应 `CAPSULE_APPEAR`。另有 `CAPSULE_WIDTH_CHANGE`、`CAPSULE_SEIZE`、`CAPSULE_BUBBLE_SWITCH`、`CAPSULE_UPDATE_DATA_WITHOUT_ANIM` 等胶囊生命周期事件。识别仍以原生枚举语义为依据，混淆类只用于当前固件适配。

系统继续承担前台任务的退出/缩小过程。模块在宿主提供到达/显示胶囊的可靠事件时衔接：预先绑定目标胶囊的真实内容和尺寸，在目标附近以短距离位移和轻微压缩起步，展开宽度并用阻尼回弹停稳。目标图标和文字跟随同一 Body 入场，不先显示完整胶囊再播放另一段动画。

不伪造整个前台应用缩成胶囊的全屏截图。若宿主未暴露可用的应用转场几何，使用目标附近的小幅衔接，不凭空推断应用起点。需要同时验证首次进入和已有服务被新服务接替：前者创建一次会话，后者在同一 Body 内连续改宽和更新内容。

就绪以内容绑定/布局和原生事件为条件，不靠固定延时猜测系统动画结束。迟到内容先保持当前有效画面，有限等待后恢复原生路径并记录原因。不得长期压制没有替代画面的原生胶囊。

## 胶囊样式

直接复用旧版胶囊配置含义：高度、圆角、模糊、颜色/透明度、应用色强度，mini 和普通形态分别读真实内容。未开启自定义的参数读取原生值。

胶囊端点采用胶囊参数，卡片端点采用展开卡片参数。插值期间保持同一材质宿主与轮廓，防止把卡片的背景固定套到胶囊。圆角、描边、背景和内容裁剪一致，并限制半径不超过当前短边的一半。

样式热更新作用到现有独立对象，不要求下一次点击才刷新。日夜模式、密度、横竖屏、屏幕 cutout 改变后重新测量目标并更新原生材质。保持模板图标、计时、文本和卡片按钮的原生语义。

| 可访问性 | 独立绘制仍向辅助功能暴露可用的原生节点/动作及正确屏幕边界，去除重复不可见节点 | 节点检查与 TalkBack 可用操作验证 |

输入适配使用同一份绘制变换求逆，涵盖位移、内容缩放和屏幕坐标。一个 DOWN 到 UP/CANCEL 归同一目标和映射上下文；动画、服务替换和销毁不能把半个手势发给新目标。保留 pointer id、时间戳、多指、速度信息和 raw 坐标语义。只移动局部坐标不足以证明这些条件成立，须真机验证。

## 窗口、绘制和性能

保留独立窗口。优先让窗口在一段动画内使用起终点及有限回弹所覆盖的固定承载范围，在其内部更新 Body 的原生材质、局部尺寸、平移和轮廓。窗口尺寸只在必要的场景边界调整；先验证当前固件 ViewRootManager 的模糊 Drawable 能正确限制在 Body 区域。

触摸 region 始终跟随实际形状，固定承载窗口的透明区域不得遮挡状态栏和应用，也不得改变原生卡片窗口的外部点击与返回职责。如果该固件内部 blur 限制不成立，应先调整原生材质绑定方式并测量，不以每帧窗口重建作为默认兜底。

就绪检查、材质初始化、内容源解析不在每帧重复反射和分配；稳定后只随真实源刷新或运动请求重绘，避免恒定 pre-draw 自激循环。对帧路径、窗口 relayout 次数和 BLAST 行为分别采样。

## 代码职责与执行顺序

本节给出设计阶段的交付切片；用户确认后由 writing-plans 技能补成逐步骤实施计划。

1. **原生行为基线和回归用例。** 保留现场证据，稳定重现重复点击，列出可用模板；补首次胶囊入场、目标替换、真实内容与绘制/触摸变换的失败用例。
2. **统一会话。** `CloudMorphHook` 负责原生场景观察与会话生命周期；抽出胶囊目标解析和版本更新，覆盖创建、更新、宽度改变、退出及各跳回应用路径。
3. **持久 Surface 与样式。** `CloudMorphSurface` 负责窗口、原生材质、内容绘制和可见性清理；为较复杂的内容绑定、材质或输入责任设置独立的小型适配类，避免继续堆进 Body。新建类随实际接口确定，不先搭空层。
4. **连续运动。** `CloudMorphTiming` 及必要的运动状态类负责可重定向曲线/弹簧；接通展开、收起和前台进入的同一几何状态，分离内容进度。
5. **原生交互恢复。** 用专门的输入适配维护根容器、绘制逆变换和手势所有权；按上述清单回归按钮、长按、滑动、外部点击、返回、应用跳转和辅助功能。
6. **验证和文档。** 修正真实 Surface 的测试盲区，完整编译和回归，安装到已授权手机，重启 SystemUI 后核对新 PID 和模块版本，录制场景并采样。更新现有动画链路文档，明确实际验证范围。

## 验证与完成条件

主机层执行实际 Hook/运动/输入数学代码，覆盖：原生生命周期对象身份；首次出现不依赖卡片；零 override 和 mini 占位；半途反向位置/速度连续；目标服务替换；回弹边界；样式热更新；旧代次隐藏不影响新场景；禁用、锁屏、旋转、系统禁用动画的清理。每个修复先有可重现失败，再验证通过。

保留现有 JVM 合成检查对平台边界的适度替身，但必须新增真实 `CloudMorphSurface` 的 Android 编译和设备验证。触摸变换、会话代次等纯逻辑不再让无行为替身代替生产代码。测试命令基础为：

## 自审结果

范围覆盖用户提出的四项工作；现状与拟议改动分别标明。轻回弹尊重已有 0 回弹语义，不重置用户设置。方案不依赖重做原生任务转场，不回退状态栏视觉绑定；宿主事件语义和模块设置页组件约束各自适用。

当前剩余不确定性是：重复点击失败的稳定触发条件、当前固件内部材质在固定承载窗口中的裁剪、以及设备当前具备哪些多服务/即时卡片数据源。它们均有明确的验证步骤和交付条件，不作为已经解决的结论。
