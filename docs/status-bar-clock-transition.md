# 状态栏时钟与通知中心过渡

适配依据为本地设备的 C17 SystemUI：通知中心使用 `OplusSimpleQSFakeController`，其 `fakeClockViewContainer` 中的 `StatusBarFakeFrame` 直接绘制绑定的状态栏 `StatClock`。通知中心最终显示的 `SimpleQsClock` 保留系统格式和字号。

原生控制器给两个时钟应用相同的缩放值，并以通知中心时钟的基线计算替身视图的缩放中心。这要求两个时钟具有相同的基础文字尺寸。状态栏的自定义字号、日期/星期前缀和横向压缩破坏了这个前提。

`StatusBarClockTransitionHook` 保留系统提供的进度、透明度、字体缩放和大显示模式上限，在这些计算后修正时钟的几何数据：

- 用各自 `Layout` 中“时:分”的实际位置作为横向锚点，包含日期前缀、压缩与 RTL 产生的偏移。
- 替身以状态栏时钟自己的基线缩放；通知中心时钟以自己的基线缩放。
- 将原生的中心点位移换算成文字基线位移，将固定边缘留白换算成时间文字锚点位移。
- 基线位移仅补偿两个时钟视图，不改写系统同时用于通知图标的纵向位移字段。
- 两端分别插值字号比例和横向文字缩放比例，使替身与通知中心时钟在同一进度下具有相同的文字尺寸。
- 保留收起端状态栏时钟的原始尺寸，以及展开端通知中心时钟的原生尺寸。关闭自定义与压缩后，直接使用原生计算。

`StatusBarClockHook` 还在 `StatClock` 测量和发布布局区域前同步分钟宽度与完整宽度，防止系统继续使用自定义字号/压缩之前的缓存。配置更新会使通知中心的布局计算失效，下一次过渡重新读取几何数据。普通时钟测量不修改动画的布局失效标记，避免秒数刷新在手势中途触发原生的动画中断分支。

回归检查运行实际生产 Hook，使用提取出的原生位置、基线和缩放公式作为系统替身，覆盖展开与收回、多种进度、日期/星期/秒数、压缩、RTL、本地化数字、大显示模式上限、重复计算与关闭功能。该检查验证几何关系，不代替真机逐帧视觉验证。

```powershell
$env:JAVA_HOME='D:/java17'
python scripts/check_effects.py --only StatusBarLayoutCheck StatusBarClockTransitionCheck
```
