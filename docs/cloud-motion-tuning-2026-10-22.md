# 流体云展开性能与回弹调整

这是 `cloud-motion-overhaul-2026-10-22.md` 之后的增量修订，针对展开卡顿、回弹影响整体速度，以及曲线观感。修改限于宿主 Hook 和绘制桥接，保留用户设置与业务服务。

## 最终运动方案

用户指出首个修订版的曲线与回弹更难看。因此撤回该版对缓出曲线采用的 55%–80% 人为停靠、新增 S 曲线及固定回弹脉冲。最终缓出三档恢复连续解析弹簧与原有响应差别，保留末端 60%–100% 的 C2 收敛包络。

旧代码将回弹用于阻尼，同时以 `response / damping / duration` 提高自然频率。改为按期望超出幅度推导阻尼，再求解对应的半程时间，校准响应频率。静止起步时，回弹 0/25/50/100 的到达一半位置时间一致，总时长也一致；各时刻的瞬时速度仍会随回弹形态发生变化，不能称为所有时刻轨迹完全相同。最大档期望的自然超出量约为行程的 4%，末端包络可能略微压低实际峰值。

反向时，继承的手势速度通过独立临界阻尼项耗散，避免调大回弹后放大已有动量。位置、速度和加速度均为解析值，没有逐帧积分，也不在缓出曲线中拼接人为回弹时段。

- iOS 式缓出、平滑缓动、轻快缓出恢复原有 9/8/10 的响应差别，不扩大曲线间的观感差异。
- 匀速保持线性主体，不再在回弹为非零时切换为另一条缓出弹簧；其末段仍需有限停靠段来容纳可选回弹，区别于前三条连续弹簧。
- 六个通道共享每帧的指数与三角函数计算；同一进度继续缓存位置、速度与加速度。

## 展开性能处理

真机跟踪显示展开/收起期间存在大量 measure/layout。代码每次轮廓尺寸变化先 `setLayoutParams` 请求布局，又立即执行同步 measure/layout，触摸区域变化随后再次请求布局。

保留同步几何更新，直接更新已有子布局参数，避免重复请求整窗布局。触摸区域通过绘制遍历刷新；已检查本机 `ViewRootImpl.performTraversals`，存在 `OnComputeInternalInsetsListener` 时，绘制遍历会计算内部触摸区域，不依赖每次重新 measure/layout。

将精确原生轮廓的输入区域缓存到当前显示帧；动画更新、透明度更新与原生 pre-draw 重复观察同一帧时，不重复生成路径和扫描转换 Region。输入开关、月牙与多卡片区域合并仍即时更新。

## 校验与交付

新增轨迹回归覆盖半程时间校准、回弹幅度递增、自然峰值不被钉在 80%、时间缩放与原有曲线响应。新的回归在用户否定的修订版上失败，在连续弹簧版上通过。继续执行反向继承、边界夹取、原生入口、多卡片和文字渲染校验。

连续弹簧修订版已完成构建与一轮设备采样；随后用户反馈内容颤抖，已修复原生外壳宽度动画重复缩放内容的问题，并安装 `thunder-cloud-content-stable-20261022.apk`。用户手动测试后要求停止真机复测，继续做源码及性能审查，结果见 [动画审查记录](cloud-animation-audit-2026-10-22.md)。原始跟踪、日志及截图位于 `.local/cloud-tuning-20261022/`。早期两次零绘制帧采样无效；后续有效采样属于修复前版本，不能用来认证审核优化包的帧率。
